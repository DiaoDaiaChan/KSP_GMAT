# 🌌 MGA 引力必吃榜、顶层优化器、高价值参数体系、魔法数字收拢与历史任务调试器实施方案

## 1. 目标与背景 (Objective & Background)

用户核心指导思想：
1. **“参数最好不要固定死，能根据求解器自动求解，或者给出高价值的可以调参数。”**
2. **“创建一个最顶层优化器，接收高价值可调参数，传递给下面。”**
3. **“如果未能求解，尝试优化参数以及编写新的算法，而不是尝试针对性修复编写硬编码。”**
4. **“给每个行星一个‘引力必吃榜’（即可以借到的动能，自动计算，不要硬编码行星），将它们归一化加入计算，让求解器总是去借大行星的力，避免求解序列缺失。”**
5. **“现在各个求解器，优化器的数据有没有双向联动？”**
6. **“为了确保优化算法的可行性，我们加入一些历史任务，确保它能找到历史任务的最优解，但是不要为了达成历史任务而编写代码。历史任务作为调试器，加强各个求解器的强关联。”**
7. **“将散落在各个优化器求解器的经验魔法数字收集起来。”**

### 系统演进目标
构建**清晰三层架构**的深空多重引力助推 (MGA) 轨迹综合设计引擎：
- **顶层 (Tier 1: Master Orchestration)**:
  `MGAMasterOptimizer` 最顶层优化器，面向航天任务设计师，接收高层工程决策变量 `MGAHighValueParameters`（高价值物理/算力权衡参数），提供一键式工程预设，负责全局生命周期调度与参数自适应转译下发。
- **中层 (Tier 2: Discrete Topology & Domain Filtering)**:
  天体“引力必吃榜”吸附高能量跳板，SPICE 真实星历与开普勒 Vis-Viva 联合图搜索，生成无跳级断层的引力阶梯拓扑池。
- **底层 (Tier 3: Continuous Multi-Island DE & Native Dynamics)**:
  双向联动多岛差分进化，共享航段基因迁移，早期赤字熔断，底层 100% 官方 ESA kep3 Native C++ 动力学闭环。
- **全局真值源与调试裁判**:
  集中注册的 `MGADefaults` 消除散落魔法数字；通用的 `MGAHistoricalMissionDebugger`（Voyager 2, Galileo, Cassini, BepiColombo）充当零特判黑盒调试裁判。

## 3. 高价值可调参数体系 (MGAHighValueParameters) 详尽设计

高价值可调参数是航天任务设计师、轨道力学工程师直接关心的**物理边界、任务约束、安全走廊与算力投资指标**。顶层优化器屏蔽了底层如 `DifferentialWeightF`, `DsmEtaDefault`, `MctsGridStepDeg` 等数十个内部实现旋钮，将其归并为 6 大维度高价值参数：

```csharp
public sealed class MGAHighValueParameters
{
    // =========================================================================
    // 维度 1: 推进系统与机动能力预算 (Propulsion Capabilities & Delta-V Budget)
    // =========================================================================
    
    /// <summary>
    /// 飞船总工质机动能力上限 (m/s)。
    /// 涵盖发射出射额外机动、中途深空机动 (DSM) 以及最终到达捕获机动之和。
    /// 典型值: 4000.0 m/s (深空巡航极限挑战) ~ 8000.0 m/s (充裕工质任务)。
    /// </summary>
    public double MaxVesselDeltaVMs { get; set; } = 4000.0;

    /// <summary>
    /// 航路中途允许施加的最大深空机动 (DSM) 上限 (m/s)。
    /// 调小该值 (如 <= 500 m/s) 可强迫求解器深度挖掘天体引力弹弓与共振滑翔，避免用工质暴力弥补相位差。
    /// 典型值: 500.0 m/s。
    /// </summary>
    public double MaxDsmDeltaVMs { get; set; } = 500.0;

    /// <summary>
    /// 始发天体停泊轨道 (如地球 LEO) 的最大允许切向注入出射速度增量 (m/s)。
    /// 对应运载火箭经停泊轨道注入双曲线逃逸轨道的最大能力 (C3 门禁)。
    /// 地球 LEO (200km) 经典 TVI 注入能力上限通常为 3800 m/s (对应 C3 ~ 20-25 km^2/s^2)。
    /// </summary>
    public double LaunchDeltaVCeilingMs { get; set; } = 3800.0;

    /// <summary>
    /// 目标天体到达双曲过剩速度上限 (km/s)。
    /// 若任务要求捕获入轨，过高的 v_inf_arr 将导致天文数字般的刹车推进剂消耗；
    /// 设为 0 表示不加限制 (高速飞掠掠飞模式)。
    /// </summary>
    public double MaxArrivalVInfKms { get; set; } = 0.0;

    /// <summary>
    /// 强制严格无动力双曲弹弓 (Strict Unpowered Flyby)。
    /// 若为 true，借力天体近拱点机动 DeltaV_fb 必须严格为 0.00 m/s，禁止在引力井内通过脉冲“作弊”硬转角。
    /// </summary>
    public bool StrictUnpoweredFlyby { get; set; } = true;


    // =========================================================================
    // 维度 2: 引力辅助策略与爬升网络 (Gravity Assist Hierarchy & Adsorption Network)
    // =========================================================================

    /// <summary>
    /// 天体“引力必吃榜”吸附阈值 (归一化比率，0.0 ~ 1.0)。
    /// 以太阳系引力最强天体 (木星 = 1.0) 为基准。只有引力效能比率 >= 该阈值的天体才允许作为梯级跳板。
    /// 默认 0.025 (即仅吸收木星、土星、地球、金星，过滤引力极其微弱的小天体，防止序列漫无目的发散)。
    /// </summary>
    public double MinGravityPowerRatio { get; set; } = 0.025;

    /// <summary>
    /// 单个天体允许的最大连续共振借力次数 (1 ~ 5)。
    /// 例如水星 1:1, 2:1, 3:2, 4:3 共振泵升；或地球 2:1 轨道周期抬升。
    /// 调大允许深入内/外太阳系时进行多轮换轨，调小减少任务操作复杂度。
    /// </summary>
    public int MaxResonancesPerBody { get; set; } = 5;

    /// <summary>
    /// 是否允许交错双星共振泵升 (Interleaved Resonant Pumping, 如 Earth -> Venus -> Earth -> Venus)。
    /// 经典深空探测 (Galileo VEEGA, Cassini VVEJPS) 必备策略。
    /// </summary>
    public bool AllowInterleavedResonances { get; set; } = true;

    /// <summary>
    /// 飞往外太阳系深空 (目标半长轴 > 4 AU，如木星外侧、海王星) 时，是否强制吸附巨行星超级弹弓。
    /// 彻底切断内太阳系天体直接跳跃至外太阳系的无解拓扑。
    /// </summary>
    public bool RequireOuterGasGiantAssist { get; set; } = true;

    /// <summary>
    /// 全航程允许经过的最大借力天体总次数 (Intermediate Flyby Legs 上限)。
    /// 典型值: 3 ~ 8 次。
    /// </summary>
    public int MaxIntermediateFlybys { get; set; } = 8;


    // =========================================================================
    // 维度 3: 航天器物理走廊与空间环境安全 (Thermal, Solar & Environmental Corridor)
    // =========================================================================

    /// <summary>
    /// 航天器全航程允许的最小近日距 (AU)。
    /// 由防热罩与太阳辐射热控极限决定 (例如接近水星轨道约为 0.31 AU)。
    /// 严禁轨迹下探至该距离以内，防止热控超标烧毁。默认 0.28 AU。
    /// </summary>
    public double MinSolarDistanceAu { get; set; } = 0.28;

    /// <summary>
    /// 航天器全航程允许的最大远日距 (AU)。
    /// 由供电形式决定：若为太阳能电池驱动，通常 <= 2.5 AU (木星轨道以内光照急剧衰减)；
    /// 若为放射性同位素热电机 (RTG)，可设为 50.0 AU。默认 35.0 AU。
    /// </summary>
    public double MaxSolarDistanceAu { get; set; } = 35.0;

    /// <summary>
    /// 飞越借力天体时的大气层/地表最小安全净空高度 (km)。
    /// 提供 3-sigma 导航误差下的防撞走廊与避开危险辐射带缓冲。
    /// 默认 50.0 km (自动叠加大气厚度)。
    /// </summary>
    public double FlybySafeAltitudeMarginKm { get; set; } = 50.0;


    // =========================================================================
    // 维度 4: 任务寿命、航时与时序边界 (Mission Lifetime & Temporal Constraints)
    // =========================================================================

    /// <summary>
    /// 任务全寿命最大飞行时间上限 (年)。
    /// 受到航天器元器件总辐射剂量 (TID) 与 RTG 半衰期限制。
    /// 例如海王星/外行星任务通常限制在 15.0 ~ 25.0 年。
    /// </summary>
    public double MaxTotalMissionDurationYears { get; set; } = 25.0;

    /// <summary>
    /// 任务允许的最短总飞行时间 (年)。
    /// 防止搜索空间挤压到非物理的高能直飞盲区。默认 0.5 年。
    /// </summary>
    public double MinTotalMissionDurationYears { get; set; } = 0.5;

    /// <summary>
    /// 发射窗口全局搜索跨度 (天)。
    /// 典型值: 800 天 (~2.2 年)，覆盖常见行星会合周期 (Synodic Period)。
    /// </summary>
    public double LaunchWindowSpanDays { get; set; } = 800.0;

    /// <summary>
    /// 连续同星共振单次最大允许等待时间 (年)。
    /// 避免航天器在单星轨道滞留数十年等待罕见几何构型。默认 3.0 年。
    /// </summary>
    public double MaxResonanceWaitYears { get; set; } = 3.0;


    // =========================================================================
    // 维度 5: 多目标帕累托权衡与优化偏好 (Multi-Objective Trade-Off & Priority)
    // =========================================================================

    /// <summary>
    /// 任务优化导向优先级。
    /// FuelOptimal (极低能耗) / TimeOptimal (快速到达) / BalancedPareto (帕累托折衷)。
    /// </summary>
    public ObjectivePriority Priority { get; set; } = ObjectivePriority.FuelOptimal;

    /// <summary>
    /// 帕累托边际换算比率 (m/s 速度增量 / 年 飞行时间)。
    /// 工程权衡核心：为使飞行时间缩短 1 年，任务设计方愿意额外支付多少 m/s 的 Delta-V？
    /// 默认 150.0 m/s / 年。
    /// </summary>
    public double ParetoTradeoffRatioMsPerYear { get; set; } = 150.0;

    /// <summary>
    /// 发射能级 C3 相对中途深空机动 (DSM) 的惩罚权重 (0.5 ~ 2.0)。
    /// 默认 1.0 (等价折算)。若运载能力极为紧张，可调大至 1.5。
    /// </summary>
    public double LaunchC3Weight { get; set; } = 1.0;


    // =========================================================================
    // 维度 6: 算力预算、演化深度与双向联动调度 (Compute Budget & Bi-directional Dispatch)
    // =========================================================================

    /// <summary>
    /// 一键算力预设档位 (QuickReconnaissance / StandardEngineering / ExtremeDeepSpaceChallenge)。
    /// </summary>
    public ComputeBudgetPreset ComputePreset { get; set; } = ComputeBudgetPreset.StandardEngineering;

    /// <summary>
    /// 竞争拓扑候选池规模 (4 ~ 16)。
    /// 决定中层 MCTS 拓扑引擎推演并交付底层并行进化的候选链条总数。默认 8。
    /// </summary>
    public int CandidateTopologyPoolSize { get; set; } = 8;

    /// <summary>
    /// 单岛进化种群规模 (50 ~ 150)。
    /// </summary>
    public int PopulationPerIsland { get; set; } = 100;

    /// <summary>
    /// 差分进化最大迭代代数 (80 ~ 300)。
    /// </summary>
    public int MaxGenerations { get; set; } = 150;

    /// <summary>
    /// 是否启用拓扑-优化器双向联动：优势拓扑发射历元动态对齐 (Cross-Topology Launch Window Centering)。
    /// </summary>
    public bool EnableBiDirectionalEpochCentering { get; set; } = true;

    /// <summary>
    /// 是否启用早期不可达物理赤字熔断 (Early Deficit Pruning) 与代数自适应再分配。
    /// </summary>
    public bool EnableEarlyDeficitPruning { get; set; } = true;
}
```

### 4.3 内部四阶段执行管道 (Four-Stage Execution Pipeline)

1. **Stage 1: 物理势阱与引力必吃榜动态评估 (`EvaluateGravityAssistHierarchy`)**
   - 纯物理推算当前始发/目标跨越关系。
   - 调用 `SolarSystemCatalog.GetGravityAssistRankings()`，计算各天体 $\Phi_{safe} = \mu / r_{safe}$ 与 $\Delta v_{max}(v_\infty)$。
   - 筛选出相对王者天体比率 $\ge \text{MinGravityPowerRatio}$ 的强效引力中继体。
2. **Stage 2: 离散拓扑树生成与防跳级阶梯吸附 (`GenerateConsistentTopologyPool`)**
   - 根据起点/终点与意向天体，强制在跨引力势阱时吸附高位跳板（例如深井水星到远外海王星时，强制必须经金星/地球/木星梯级过渡）。
   - 彻底阻断不符合机械能梯级的跳级序列。
   - 生成 $N$ 个具备严格物理可行性的高质量拓扑候选。
3. **Stage 3: 双向联动多岛差分进化求解 (`RunBiDirectionalContinuousOptimization`)**
   - 将 `MGAHighValueParameters` 自动映射生成各自拓扑的 `MGAAdaptiveSolverConfig`。
   - 启动并行差分演化：
     - **历元对齐联动**: 优秀拓扑的最优发射历元 $t^*$ 实时反馈，将后续拓扑搜索区间自动聚焦在 $t^* \pm 45\text{ 天}$。
     - **基因注入联动**: 共享相同前驱借力天体的拓扑，将高质量个体直接作为种子注入同类拓扑。
     - **赤字熔断联动**: 演化前 25 代若最优解能量赤字仍 $> 4000\text{ m/s}$，则熔断该拓扑，将剩余代数算力动态转拨给优势梯级拓扑。
4. **Stage 4: 100% 官方 ESA Native C++ 动力学校验与数学报表导出 (`VerifyAndExportReport`)**
   - 经底层 Native kep3 严谨校验。
   - 调用 `MGAMathDiagnosticReport` 输出结构化物理与数学指标至 `reports/mga_math_diagnostic_report.md`。

## 5. 散落经验魔法数字集中收拢与语义注册 (`MGADefaults`)
*在 `src/KSPGMAT/Model/MGAStateManager.cs` 的 `MGADefaults` 中集中注册并附带详尽物理理论注释，彻底杜绝裸字面量*

1. **引力势阱与梯级爬升常数**:
   - `GiantAssistDistanceRatio = 3.0`: 触发巨引力弹弓的外轨半长轴倍率门槛
   - `GravityClimbingDistanceRatio = 2.0`: 触发梯级爬升插序的跨越倍率
   - `InnerSystemMaxSmaKm = 4.0 * AU_KM`: 内太阳系天体半长轴上限 ($4\text{ AU}$)
   - `MinAssistPowerIndexInner = 35.0`: 内行星具备显著借力效能的引力势深下限 ($\mu / r_{safe} \ge 35\text{ km}^2/\text{s}^2$)
   - `GiantPlanetMinMu = 1.0e7`: 巨行星天体引力常数下限 ($\mu \ge 10^7\text{ km}^3/\text{s}^2$)
   - `MinSteppingStoneMu = 500.0`: 梯级跳板天体最小引力常数门槛

## B.6 说明与待确认点

1. **文件归属**：`MGAConfigurationTranslator` 可并入 `MGAMasterOptimizer.cs`（一个文件内 `partial`），避免文件碎片化；若拆两个文件更清晰，按"M3"二选项之一执行，改动范围可控。
2. **历史任务真实解数据源**：Voyager 2 / Galileo / Cassini / BepiColombo 的关键借力序列与发射历元为**文档常数**（真值表中的对照基准，非求解常数），建议放 `tests/MGADebugRunner` 内的静态只读表（`HistoryMissionGroundTruth`），仅供比对、**不参与求解**（呼应"不要为了达成历史任务而写代码"）。
3. **`MinGravityPowerRatio` 默认 0.025**：与现有默认 `EnableAlternatingPumping` 等组合后可能需要微调避免把地球/金星排除；M5 阶段用 `GetGravityAssistRankings` 实测排名后再定默认值是否保持。
4. **性能**：`history` 与 Scenario 9 全量跑可能耗时；建议复用现有 `MaxCandidateTopologies=8` 档位，避免默认全量 100 代导致调试等待过久。
