# KSPGMAT 项目专业性与严谨性评估报告

> 评估日期：2026-09-08
> 评估范围：`src/KSPGMAT`（47 个源码文件，约 3 万行 C#）+ `paper/` 论文实现文档 + `tests/` 基准测试 + 构建/部署配置 + Git 历史
> 结论：**未修改任何代码**，仅出具审查报告

---

## 1. 项目概况

KSP 模组插件，将 NASA GMAT（通用任务分析工具）与 ESA PyKEP/kep3 原生求解器集成到 KSP 中，实现真实轨道力学仿真与多目标重力辅助（MGA）寻优。核心分层：

- **互操作层**：`KSPGMATBridge`、`MechJebInterop`、`PrincipiaInterop`、`ROEngineInterop`
- **核心业务**：`GMATClient`、`GMATStateManager`、`GMATDynamicOverrides`
- **科学计算**：`MGA/`（MGA 自适应求解、猪排图、历表、Pykep P/Invoke）
- **服务层**：`Service/`（脚本生成/解析/校验/diff/控制台运行器）
- **UI 层**：`UI/`（IMGUI 主窗口 16 个 partial 文件）

## 3. 专业性强项（亮点）

### 3.1 论文→代码映射严谨可追溯

`paper/论文实现要点_公式直达.md` 中规划的每个模块都真实落地且参数一致：

- `MGAMCTSTopologySelector`、`MGASurrogatePreFilter`、`MGAArchipelagoOptimizer`、`MGASelfHealingEngine` 全部存在于 `src/KSPGMAT/MGA/MGAAdaptiveSolver.cs`（L209 / L733 / L790 / L872）
- 论文参数精确对应：`IslandCount=4`、`MigrationPeriod=10`（多岛 DE §5，见 MGAAdaptiveSolver.cs L99-L100）、`HohmannEnergyCeilingFactor=1.35`（自愈判据，L112）
- 公式边界严谨：文档明确标注论文未给出的内容（如 §3 综述"未给出 MGA 公式"），不虚构出处

### 3.2 数值红线执行到位

- `PykepNative.SolveLambert`（`src/KSPGMAT/MGA/PykepNative.cs` L473-L503）：Lambert 100% 走原生 `pykep_lambert_solve`，含 `tof<=0 || mu<=0` 参数拒绝，失败时明确日志"严禁托管自编公式拟合"
- 托管层仅做解析几何遥测回填（`MGAFlybyDynamicsHelper.cs` L32-L99：双曲偏转角 δ、`e=1/sin(δ/2)`、`rp=μ/v∞²(e−1)`、B 平面投影公式均正确），并做了完整奇异性保护：`cosDelta` clamp、`sinHalf>1e-6` 阈值、`hCross` 退化回退、开方负值保护

### 3.3 基准测试含真实历史任务

`src/KSPGMAT/MGA/MGABenchmarkSuite.cs`（L457-L601）以 Mariner 10、Galileo VEEGA、Cassini VVEJPS 等真实任务的历史 ΔV/ToF 作为通过判据，并检查矢量连续性、飞掠可行性——轨道力学工程中较严肃的验证方式。

### 3.4 本地化架构专业

`src/KSPGMAT/I18n.cs`（L17-L103）支持动态加载、指纹热重载、语言自动探测（KSP 语言→系统区域回退）；4 个语言文件（zh/en/jp/ru，各 100KB+）完整。手写 JSON 解析器正确处理转义与 `string.Format` 占位符。

### 3.5 其他

- **无 TODO/FIXME/HACK 残留**（全库搜索 0 命中）
- Git 提交信息规范（`feat/fix/docs/refactor` 前缀，语义清晰）
- 构建开启 `Deterministic=true`；统一日志门面 `KSPGMATLog`（分级 + Unity 环境回退）

## 4. 严谨性短板（按严重程度排序）

### 🔴 严重

**S1. 外部进程管理存在死锁与超时失控**

`src/KSPGMAT/Service/GMATConsoleRunner.cs` L113-L120：

```csharp
stdout = process.StandardOutput.ReadToEnd();   // 先同步读满 stdout
stderr = process.StandardError.ReadToEnd();    // 再读 stderr —— 若子进程大量写 stderr 会缓冲填满而死锁
process.WaitForExit(45000);                    // 返回值被忽略：超时后进程不 Kill，ExitCode 访问会抛异常
```

- stderr 缓冲（默认 4KB）填满而 stdout 尚未读完时，GmatConsole 阻塞 → 无退出 → 永久挂起
- `WaitForExit(45000)` 超时后既未终止进程，也未处理超时分支
- 应改为异步 `BeginOutputReadLine`/`BeginErrorReadLine` 并行读取 + 超时 Kill

**S2. 40+ 处空 catch 吞掉全部异常**

分布于 `GMATClient.cs`（L442/L492/L499/L516/L558/L686）、`I18n.cs`（L286-L292）、`KSPGMATSettings.cs`（L38/L72）、`GMATParameterRegistry.cs`、`PrincipiaInterop.cs` 等。

- SPICE 星历加载、配置写入、目录创建等关键路径失败时无任何日志，用户遇到的"灵异现象"无法排查
- 部分空 catch 在容错上下文可接受（如 `KSPUtil.ApplicationRootPath` 探测），但配置**写入**失败（Settings L72）和 SPICE 加载失败（L38）静默必须至少降级为 Warn 日志

**S3. 构建配置不可移植**

`src/KSPGMAT/KSPGMAT.csproj` L15-L62：9 个程序集引用全部硬编码本机绝对路径 `C:\Program Files (x86)\Steam\steamapps\common\Kerbal Space Program_newmod\...`。换机器/换盘符即无法编译；应改为相对路径或 `$(KSP_ROOT)` 属性注入。

### 🟡 中等

**M1. 脚本生成存在转义盲区**

`src/KSPGMAT/Service/GMATScriptGenerator.cs` L38-L73：

- SPK 路径仅做 `\`→`/` 替换后包单引号，未处理路径内含 `'` 的情况
- 动态扩展属性 `{satName}.{key} = {value};` 直接拼接，无标识符/引号校验——当前来源可信但属脆弱点

**M2. 文档引用悬空与红线口径不一致**

- `paper/论文实现要点_公式直达.md` L5 引用 `论文重点直达_ESA.md`，但 `paper/` 目录中不存在该文件
- 文档称"飞掠全部在 Native C++ 闭环"，但 `MGAFlybyDynamicsHelper.cs` 在托管层实现了飞掠几何解析计算——红线声明与实现边界存在口径不一致（可辩护为"遥测回填非动力学约束"，但应明确注释区分）

**M3. 硬编码路径与中英混杂错误文案**

- `GmatBinPath` 候选含 `C:\GMAT\bin`、`D:\GMAT\bin`（`GMATClient.cs` L421-L428）；`FindGmatConsoleExe` 全找不到时返回不存在的 `candidates[0]` 而非 null，逻辑绕
- 错误消息部分硬编码中文（`GMATConsoleRunner.cs` L62），未走 i18n，与本地化架构不统一

**M4. 线程可见性**

`GMATClient.IsConnected`/`ServerStatusText` 为 public static 可变字段，后台线程写入、UI 线程读取，无 volatile/锁（`mainThreadQueue` 本身用 lock 保护是正确的）。

### 🟢 轻微

- **UI 单文件过大**：`GMATMainWindow.TabSequence.cs` 3028 行、TabMGA 2293 行、Widgets 2227 行，虽 partial class 拆分合理，但单文件仍超可维护阈值
- **二进制产物入版本库**：`GameData/KSPGMAT/Plugins/KSPGMAT.dll`、`native/*.bin` 被 git 跟踪，提交噪声大
- **构建产物目录冗余**：`bin/`、`obj/` 的 Debug/Release 双份均在源码树内
- 注释语言中英混杂（同一文件 `/// 中文` 与英文说明混排），不影响功能但影响一致性

## 5. 值得肯定的工程细节

- `KSPGMATLog` 分级日志 + Unity 环境回退，失败路径不抛异常

## 6. 优先改进建议（按投入产出比）

1. **S1 进程管理重写**（最高优先）：并行异步读 stdout/stderr，超时 Kill，是唯一的潜在死锁点
2. **S2 关键路径空 catch 补日志**：SPICE 加载、配置写入、进程启动失败至少记 Warn
3. **S3 csproj 路径参数化**：改成相对路径或 `$(KSP_ROOT)` 属性，一次修改永久受益
4. 错误文案纳入 i18n；补 `论文重点直达_ESA.md` 或删除引用
